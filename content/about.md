## 为什么要有这个站

写 DSH 插件的文章有个特点：同一批插件被翻来覆去地讲，名字还不一定一致。有的叫 `dsh-web-ui-all`，有的叫 `@linxin666/dsh-web-all`，其实是同一族东西；有的文章把「多 Agent 团队」写成社区插件，官网上它却是内置的 Experimental 项；还有星标数、仓库数这类数字，各篇统计的时刻和口径都不一样。

把这些文章一篇篇收藏，等于把混乱原样搬进收藏夹。所以本站做三件事：**同一插件合并成一条主档**、**每篇文章的说法挂成证据链**、**打架的说法单独摆出来**。

## 三层结构

| 层 | 文件 | 作用 |
| --- | --- | --- |
| 来源台账 | `data/sources.yaml` | 一篇文章一条：标题、发布方、原文链接、日期（没有就写「待补」）、这篇在本站的角色 |
| 插件主档 | `data/plugins.yaml` | 一个插件一条：名字、别名、分类、简介、安装方式、仓库、以及 `mentions` 证据链 |
| 口径核对 | `data/discrepancies.yaml` | 一篇文章里对不上的说法：各方原话并列 + 本站怎么处理 |

`python3 tools/build_data.py` 会校验引用完整性（引用了不存在的来源直接报错）、算每个插件的来源数与印证数、生成插件页 / 来源页 / 搜索索引 / 首页统计，然后 `hugo --minify` 出静态站。

## 徽章怎么来的

- **多篇印证**：两个以上不同来源提到同一个插件，且没有互相矛盾的说法。
- **单篇提及**：目前只有一处出处，标记出来提醒自己别当成共识。
- **口径有出入**：证据链里至少一条 `stance: 有出入`，卡片会挂橙标，详情页能看到双方原话。
- **补充**：角度不同但不冲突，比如一个讲功能、另一个讲安全注意事项。

同一插件被三篇文章提到，卡片会显示「3 篇印证」；只被一篇提到，就老老实实写「单篇提及」。**印证数不等于可信度**，它只说明「有几篇文章这么说过」——大家都抄同一篇通稿也会凑出高印证数，所以每条引文都保留原话和原文链接。

## 遇到说法打架怎么办

不替读者选一个「正确版本」。比如 `dsh-market` 的安装方式，公众号给的是仓库地址和 `dshmarket@1.73.6`，第三方文章给的是 `dsh plugin --profile web add dshmarket`——三条都留在证据链里，安装字段不乱填，再在「口径核对」页写清楚差异与可能的成因。

数字尤其谨慎：星标数、仓库数、插件数都是快速增长期的时间切片，计数单位还可能是「仓库 / 插件 / 标签」三种。本站一律不把这类数字写进插件卡或首页统计。

英文来源的引文是本站译述，会在页面上标注，点来源标题可以去看原文；中文来源尽量保留原话。原文没写的仓库地址、安装命令、发布日期、署名，一律留空或标「待补」，不补猜。

## 加一篇新文章（三步）

1. 在 `data/sources.yaml` 末尾加一条，`id` 用短横线小写（如 `wx-plugin-2026-11`），把原文链接贴进 `url`。
2. 打开 `data/plugins.yaml`：文章提到的插件如果已有条目，就在它的 `mentions` 下追加一条 `{source, stance, quote}`；确实没见过的才新建条目，中文名 / 英文名 / 包名都塞进 `aliases`，方便以后自动对上。
3. 跑 `python3 tools/build_data.py && hugo --minify`，然后提交生成出来的 `content/plugins/`、`content/sources/`、`static/search.json`、`data/derived.json`（这四个是产物，但**要一起进 git**，这样线上构建只需要 Hugo，不必装 PyYAML）。

如果新文章和老文章说法冲突，把 `stance` 写成 `有出入`，再去 `data/discrepancies.yaml` 加一条。重复的文章不用怕：重复的证据链正是「印证」的来源。
