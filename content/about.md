## 为什么要有这个站

写 DSH 插件的介绍有个特点：同一批插件被翻来覆去地讲，名字还不一定一致。有的叫 `dsh-web-ui-all`，有的叫 `@linxin666/dsh-web-all`，其实是同一族东西；有的把收费、免费、内测的口径混着写。

到处收藏这类页面，等于把混乱原样搬进收藏夹。所以本站的做法是：**顺着名字找到插件的官方 GitHub 仓库，读 README，把内容整理成卡片**。每条都链回仓库，一切以官方说明为准。

## 收录范围：只收需要额外安装的插件

官网开箱就带的 Subagents、Terminal、Agent loop、网页搜索，以及 Standard / Code / Minimal / Creator 四种运行模式，**一律不建条目**——不用装、也没法单独装，混进「值得装什么」的清单里只会添乱。官网界面里标为 Experimental 的内置项同样不收。

判断标准只有一条：**这个东西要不要你自己动手装一次？** 要，才收录。

## 内容从哪来

1. **找仓库**：按插件名字去 GitHub 搜，确认仓库确实是它、维护者确实是这批人。同名仓库、镜像仓、旧版分支都要分清。
2. **读 README**：确认它怎么装、依赖什么、能干嘛，以及有没有停止维护、只支持某个平台之类的限制。
3. **写卡片**：把简介、安装命令、功能亮点整理成条目，仓库地址挂上。**不写宣传话、不转述第三方评测**，README 没写的就不写。

本站**不替插件写宣传稿**，也不转载任何别人的文章正文。

## 数据结构

| 文件 | 作用 |
| --- | --- |
| `data/plugins.yaml` | 一个插件一条：名字、别名、分类、`repo`（官方仓库）、安装方式、按 README 整理的简介与功能亮点 |
| `data/categories.yaml` | 分类口径与说明 |

`python3 tools/build_data.py` 会校验每条都有可信仓库（缺 `repo` 直接报错）、算分类计数、生成插件页 / 搜索索引 / 首页统计，然后 `hugo --minify` 出静态站。

## 徽章怎么来的

- **官方发布**：插件由官方团队维护（全站只有两条）。
- **久未更新**：仓库最近一次提交在半年以前，兼容性风险更高。
- 卡片底部的「N 天前有提交」是仓库最近一次提交的距今时间，不是本站的核对时间；「本站整理于」写在每个详情页标题下面。
- **提示**：名称 / ID / 兼容性还需读者留意，例如「与另一个插件名称相近，勿混」「社区项目，非官方」。

想知道拿到安装命令之后怎么用，看[怎么装一个 DSH 插件]({{< ref "guide.md" >}})。

## GitHub 数据（星标 / Fork / 最近提交）

卡片右下角的星标数，以及详情页「速览」里的 Fork、开放 Issue、语言、License、最近提交，都来自 GitHub 公开 API：`tools/fetch_repo_stats.py` 抓取后缓存进 `data/repo_stats.json`，构建时只读缓存，出静态页不联网。

- 这是**抓取那一刻的快照**，不是实时值。想来看当下的数，点进仓库页最准。
- 数字按 GitHub 的惯例缩写（`12.9k` 即约 12,900），不精确到个位。
- 拉不到就留空，不猜、不填 0，也不拿第三方徽章服务凑数。
- **星标反映的是仓库受关注程度，不等于插件质量**：一个高星插件照样可能停更、可能和你的 DSH 版本不兼容；一个几十星的小工具也可能正是你要的那一个。看完星标，还是得读 README 的兼容性一节。
- 首页那个「星标中位数」是**中位数，不是合计**：把所有插件按星标从低到高排，取正中间那个。用中位数是因为合计会被 DSH 本体这种超大仓库一次性拉高，看不出典型插件有多大。

## 条目更新于

详情页标题下那行「条目更新于 2026-11-06」，指的是**这一条记录在本站最后一次被改动**的日期。

- 它不是插件的发布日期，也不是站点构建时间——没改动过的条目，日期不会跟着部署一起往前跳。
- 它来自 `data/plugins.yaml` 的提交历史，只在可见内容（简介、功能、安装命令、标签等）变化时刷新；内部去重台账的增删不算。
- 旁边的「仓库最近提交」是另一个口径：官方仓库最后一次 push 的日期，来自 GitHub 快照，可能滞后一天。两者并排看，能判断是「我们刚补了资料」还是「作者刚发了新版」。

## 怎么加一个插件

1. 打开 `data/plugins.yaml`，先全文搜一遍名字和别名，确认它确实还没收录（避免同一族东西建两条）。
2. 新建条目：中文名 / 英文名 / npm 包名都塞进 `aliases`，填 `repo`、`install`、`summary`、`features`，按 README 写。**官方开箱即用的内置能力不要建条目**。
3. 跑 `python3 tools/build_data.py && hugo --minify`，然后提交生成出来的 `content/plugins/`、`static/search.json`、`data/derived.json`（这三个是产物，但**要一起进 git**，这样线上构建只需要 Hugo，不必装 PyYAML）。
