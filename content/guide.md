这篇只讲「拿到一条安装命令之后怎么用」，不推荐装什么。DSH 还是开发者预览版，命令细节以官方文档和你装的版本为准。

## 先分清你用的是哪一套

同一个插件，装进哪套运行配置是由 `profile` 决定的。本站绝大多数安装命令都带 `--profile`，最常见的是 `web`，另外也会见到 `desktop`、`dsh-tui` 和个别插件作者自己起的名字。

| 你的用法 | 通常对应的 profile | 说明 |
| --- | --- | --- |
| 终端里跑 `dsh web`，用浏览器打开界面 | `web` | 最常见，本站大部分条目按这个写 |
| 装了 DSH 桌面客户端（dshdesktop.cn） | `desktop` | 但也可能读到别的 profile，见下面那条坑 |
| 只在终端里用 TUI | `dsh-tui` | 少数条目 |

## 命令行装法

基本形态就是一条：

```bash
dsh plugin --profile web add <包名>
```

- `<包名>` 照抄插件卡片上的安装命令，别自己改成仓库地址——npm 包名和 GitHub 仓库名不一定一样（比如 `dsh-market` 的仓库是 `dsh-market/dsh-market`，包里装的是 `dshmarket`）。
- 带版本号的就带上，例如 `@linxin666/dsh-web-all@latest`、`dsh-plugin-shop@0.9.2`。想要可复现就固定版本，想跟新就走 `@latest`。
- 机器上没全局装 CLI 的，官方给的是 npx 形态：`npx -y @deepseek-ai/dsh plugin --profile web add <包名>`。

## 桌面端：优先在应用里装

装了 DSH Desktop 的机器上，命令行 `add` 有可能装进 `profiles/web`，而桌面端实际读的是另一套 profile——命令返回成功，界面上却找不到。

所以桌面端请走应用内 **Settings → Plugins** 安装；实在要用命令行，先确认桌面端当前用的 profile 名再 `--profile` 指过去。

## 装完在哪确认

- 插件自带界面的（比如 `dsh-market` 这种市场类），重启后在「插件」页会多出一个标签页或入口。
- 大多数插件不新增页面，只在能力层面生效——按卡片上的「功能亮点」去对应场景试一次，比在设置里找开关快。
- 装完没反应，先看版本：不少条目要求 DSH 0.2.1+ 之类的下限，卡片「本站备注」里写了。

## 装之前值得花一分钟核对的

1. **仓库对不对**：卡片上的仓库链接点进去，看是不是这个名字、这批维护者。名字相近的仿冒仓库在这类生态里很常见。
2. **最近有没有提交**：卡片上的星标下方会写「N 天前有提交」，标了「久未更新」的要留意兼容性。
3. **它要什么权限**：DSH 插件跑在你的运行时里，等于把第三方代码放进来。装之前看一眼 README 里的权限、安装脚本和外连请求。

## 几个常见坑

- **名字对不上**：同一个插件在不同文章里叫法不同（`dsh-web-ui-all` / `@linxin666/dsh-web-all`）。用站内搜索（<kbd>⌘K</kbd> 或 <kbd>/</kbd>）搜别名，比记包名靠谱。
- **装了两个功能重叠的**：同族插件装多个容易互相抢入口，先挑一个用。
- **命令跑完没报错但没生效**：九成是 profile 装错了，回到「先分清你用的是哪一套」那节。

> 这份说明依据各插件官方仓库 README 与 DSH 官方文档整理，最后更新于 2026-11-21。命令写法随时会变，冲突时**一律以官方仓库为准**。
